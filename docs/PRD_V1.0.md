## 0. 基线、依据与阅读约定

本文件依据原对话全部可读取文字记录编写，优先采用用户最后确认的结构。原对话包含图片附件，但工具未提供可明确对应“最终定稿线稿”的完整标注稿；本文不宣称已逐张完成视觉核对，也不推断图片中的像素、尺寸或配色参数。后续 UI 规范应再与最终图稿对应。

以下三个级别用于避免把补充设计当成已确认需求：

- **已确认**：用户明确指定，或已经接受并纳入最终线稿的功能与规则。
- **落地约定**：本 PRD 为一致实现补充的路径命名、数据语义和异常处理要求，不代表原图上已标明这些细节。
- **待确认**：原对话没有唯一结论的产品选项、数值或边界；本文列出问题及必要时的建议，不将其升级为冻结规则。

本文件各节的页面与核心能力默认属于已确认范围；具体实现补充和未定项另行标注。冲突处理顺序：本次用户明确要求 > 原对话最后确认与修订 > 较早已接受规则 > 助手的建议。原对话中的技术栈建议不属于技术选型决议。

- 初期“邀请仅分享”的建议被用户明确改为实时一起拼，V1 包含多人协作。

- 对话里的“宽高比 1:1”发生在出图请求中，不能据此认定所有上传图片或拼图画布必须为正方形。

## 1. 产品目标与 V1 范围

### 1.1 产品定位

面向桌面浏览器的在线拼图网站。用户可以发现图片并立即游玩，也可以参与今日挑战、上传图片制作作品，以及邀请好友实时完成同一幅拼图。

### 1.2 核心目标

1. 降低开始游玩的成本：浏览到点击卡片即可进入普通拼图，无登录与详情页前置门槛。
2. 提供舒适的拼图体验：合理摆放碎片、拖动吸附、辅助工具、自动保存与进度恢复。
3. 建立每日回访路径：统一题目的每日挑战、明确计时、当天最佳成绩及排行榜。
4. 形成用户内容和个人积累：单页创建作品，沉淀收藏、完成与最近游玩记录。
5. 提供轻量实时协作：从当前进度发起好友一起拼，完成同一局。

### 1.3 核心闭环

- 发现：首页／搜索／分类 → 点击卡片 → 普通拼图 → 完成 → 再拼／收藏／查看个人记录。
- 挑战：首页今日挑战 → 挑战 → 完成结果 → 排行榜 → 再挑战。
- 创建：登录 → 单页上传与设置 → 创建成功 → 开始拼图／我的作品／分享。
- 协作：普通拼图 → 一起拼吧 → 创建房间 → 等待好友 → 房主开始 → 共享拼图 → 全员完成结果。

### 1.4 成效观察（落地约定）

记录进入拼图后的首次拖动率、有效开局完成率、保存与恢复成功率、创建成功率、房间创建到共同开局转化率、挑战参与与次日回访。V1 暂不设置未经验证的业务百分比目标；埋点定义见第 12 节。

## 2. 用户角色与登录策略

| 能力 | 游客 | 登录用户 | 房主／成员差异 |
|---|---|---|---|
| 浏览首页、搜索、分类、公开作品 | 可用 | 可用 | 无 |
| 普通拼图及普通辅助工具 | 可用 | 可用 | 多人另见第 7 节 |
| 浏览排行榜 | 可用 | 可用 | 无 |
| 参加挑战、成绩上榜 | 待确认 D01 | 支持 | 个人挑战，不可多人 |
| 收藏／取消收藏 | 触发登录 | 可用 | 无 |
| 创建与访问自己的私有作品 | 触发登录 | 所有者可用 | 私有作品邀请权限见 D06 |
| 创建或加入多人房间 | 触发登录 | 可用 | 房主有开始权限 |
| 我的主页及个人子页 | 触发登录 | 仅本人数据 | 无 |
| 帮助内容 | 落地约定：公开可读 | 可读 | 反馈身份要求见 D11 |

登录使用弹窗，不新增独立登录页面。右上角游客显示登录／注册，登录后全站一致替换为头像、用户名及账户菜单。第三方登录渠道、邮箱方式和账号绑定组合见 D07，不能将原对话后续推荐的 Google／Apple／Email 当成已选供应商。

**落地约定：**登录成功返回原上下文，并继续原先要求登录的动作；取消登录保留当前浏览或游玩状态。直接访问受限路由时先守卫，取消后返回可访问页面，不暴露个人数据。登录失效时允许重新登录与重试，避免丢失当前本地操作。账号切换后不得继续显示上个账号的私有列表。

普通进度需要支持自动保存与恢复；游客本地保存、登录后云端保存是建议方案，跨设备同步、游客进度迁移与冲突优先级仍待确认 D08。

## 3. 信息架构与页面路由

路由字符串为本 PRD 的落地约定；页面语义为产品基线。完成、登录、暂停等以弹窗或页内状态表达，不增加独立页面。

| 页面／区域 | 建议路由 | 主要入口与说明 |
|---|---|---|
| 首页 | `/` | Logo、返回首页；发现内容 |
| 搜索结果 | `/search?q=...` | 全局搜索；关键词与过滤条件可保留在 URL |
| 分类列表 | `/category/:slug` | 分类导航；同页切换分类 |
| 热门／编辑推荐／新上架完整列表 | `/collections/:type` | 首页查看全部；共享列表模板 |
| 普通拼图 | `/puzzle/:id` | 所有普通作品卡片直达；自动识别开始／继续／再拼 |
| 今日挑战 | `/challenge` | 首页挑战入口；绑定当天题目与挑战局 |
| 今日及往日排行榜 | `/leaderboard?date=YYYY-MM-DD` | 首页榜单、挑战结果；默认当天 |
| 多人等待／进行中／完成状态 | `/room/:roomId` | 创建房间成功、邀请链接、房间号加入 |
| 创建作品 | `/create` | 导航与首页创作入口；全流程单页 |
| 我的主页 | `/me` | 全局我的／头像入口 |
| 我的作品 | `/me/works` | 我的摘要与侧栏 |
| 我的收藏 | `/me/favorites` | 我的摘要与侧栏 |
| 我的完成 | `/me/completed` | 我的摘要与侧栏 |
| 最近玩过 | `/me/recent` | 我的摘要与侧栏 |
| 账号设置 | `/me/settings` | 个人资料、登录方式与绑定信息 |
| 消息通知 | `/me/notifications` | 我的侧栏；通知来源见 D11 |
| 帮助与反馈 | `/help` | 我的与公共帮助入口 |

禁止新增 `/puzzle/:id/detail`、作品介绍中转页，以及独立上传、裁剪、设置、预览路由。作品名、作者、片数等必要信息在卡片与拼图页展示。

弹窗／页内状态清单：登录注册、普通暂停、挑战暂停、退出确认、普通完成、挑战完成、创建成功、创建房间、加入房间、上传错误、保存失败、重连、房间失效。等待房间为同一房间路由下的状态。

## 4. 发现页面与统一卡片

### 4.1 首页

首页强调内容发现与回访。桌面主内容区域包括 Banner／Hero、搜索与分类入口、热门拼图、编辑推荐、新上架；侧栏包括今日挑战、今日排行榜摘要和创建作品入口。

- 热门、推荐、新上架可进入各自完整列表。
- 今日挑战入口进入挑战模式，普通内容卡片进入普通模式，不得仅凭图片相同混用模式。
- 排行榜摘要展示排名、用户和用时，并提供查看完整榜单。
- 搜索入口支持输入关键词并提交；不在一个页面制造互不一致的搜索条件。
- 后续 Header 可沿用已讨论的长搜索框与分类第二行方向；具体分类、模块条数和吸顶行为见 D10。

### 4.2 搜索结果页

明确展示搜索词、结果数量、有效筛选项、排序与结果列表。搜索面向作品／作者／关键词的内容发现，不因此新增作者主页。具体检索字段、筛选维度及排序口径待 D10 收口。

**落地约定：**提交新关键词重置分页；更改筛选后结果和计数同步更新；刷新和返回保留 URL 中的查询条件。无结果时提供修改关键词、清空筛选和浏览分类入口。加载失败显示重试，不伪装为零结果。

### 4.3 分类与专题完整列表

分类页显示当前分类名称、描述或作品数、分类切换和作品列表。分类用于浏览某类作品，不必填关键词。热门、编辑推荐、新上架使用共享列表能力，但标题、来源和排序应符合对应入口。

**落地约定：**提供可持续加载的列表，避免一次返回全部作品；采用分页还是加载更多由 UI 规范确定。分类不存在或下线时提示并给回首页入口。

### 4.4 卡片字段与状态

公开作品卡片固定包含图片、作品名、作者名、片数，以及游玩人数／收藏数中至少一个统计字段；最终统计字段选择见 D10。我的作品卡片优先展示创建时间、游玩人数与可见性，不重复强调自己的作者名。

| 互斥主状态 | 展示 | 点击卡片行为 |
|---|---|---|
| 未开始 | 图片、基本信息、片数 | 直接进入普通拼图并建立待操作的新局 |
| 进行中 | 基本信息 + 进度百分比 | 直接恢复对应未完成局 |
| 已完成，且无更新的未完成局 | 基本信息 + 已完成标识 | 直接进入新局，不删除历史完成记录 |

收藏是独立布尔状态，可与三种主状态叠加；悬停、键盘聚焦、加载、不可访问是交互状态，不另算游戏状态。

**落地约定：**有新一局未完成进度时，公共卡片优先显示该局进度，即使该作品过去完成过；“我的完成”列表仍保留该作品。点击收藏按钮只执行收藏，不冒泡进入拼图。收藏成功后跨列表一致，失败回滚并允许重试。卡片加载中不显示虚假的 0% 或 0 人；不可访问作品不得启动新局。

## 5. 普通拼图

### 5.1 页面布局

- 顶部：返回、作品识别信息、进度、暂停、“一起拼吧”。
- 左右：默认整齐排列的碎片托盘，各自独立纵向滚动，不要求一次铺完所有碎片。
- 中央：拼图画布，支持缩放、画布拖动与视图复位；高片数仍能定位碎片。
- 右上：默认展开的小原图浮窗，可拖动、折叠，不挤占画布尺寸。
- 底部：紧凑悬浮工具栏，打乱／边框／提示／底版；不占据大侧栏，不加入分色。

### 5.2 游玩与进度

进入后依据卡片规则新建或恢复本局。首次移动碎片后自动记录进度；普通模式不在前台突出计时，不显示“开始计时”的竞技提示。

**落地约定：**碎片拖到正确位置附近时吸附并固定，错误位置不计完成；吸附容差由拼图引擎体验测试确定。固定片数除以总片数得到进度，存储原始数量，显示百分比可取整。全部碎片固定才算完成，不用显示取整后的 100% 提前判定。

保存应包含足以恢复的棋盘与托盘状态，不仅存百分比。保存进行中、成功、失败要可辨识；失败不能显示已保存。恢复后已固定碎片、未固定位置、布局版本应一致。刷新、退出再进和网络恢复纳入验收。

### 5.3 辅助能力

| 工具 | 用户目标 | 落地约定／待定细节 |
|---|---|---|
| 打乱 | 重新整理剩余碎片 | 不重置已完成部分；待摆放碎片重新分布到托盘，具体作用范围见 D09 |
| 边框 | 更容易找到边缘碎片 | 筛选显示，不删除或改变碎片真实位置 |
| 提示 | 辅助定位 | 保留能力；具体为高亮还是自动放置、次数限制见 D09 |
| 底版 | 参考目标画面 | 显示／隐藏半透明参考图；透明度后续 UI 定义 |

暂停后显示暂停菜单与继续入口。退出时提供确认并说明进度保存状态；未保存成功不得承诺已保存。应用内退出可控，浏览器关闭时只能尽力保存，不承诺一定拦截成功。

完成弹窗提供完成反馈、再拼一次、返回发现与收藏入口；未登录收藏触发登录。再拼新建一局，历史完成记录保留。普通用时可后台记录，不进入今日挑战榜。

## 6. 今日挑战与排行榜

### 6.1 核心规则

1. 每日固定挑战题目；同一天参与者使用同一挑战配置，不能自行改变片数或拼块形状。
2. 页面准备完成后仍为待开始，首次拖动任意碎片才正式开始正计时。
3. 进行中突出“当前用时”，可显示“个人今日最佳”；本局未完成时不能将当前用时当成排名成绩。
4. 不提供提示、半透明底版、边框筛选和“一起拼吧”。挑战复用拼图基础能力，通过模式规则限制功能。
5. 可重复挑战，排行榜取每名用户当天最佳有效完成用时，按用时由短到长排序。
6. 完成弹窗展示本次成绩、今日最佳、今日排名，以及再挑战、查看排行榜。
7. 普通局和多人局完成均不能提交为挑战成绩。

挑战保留暂停入口；“暂停停止计时并遮住画布”是原对话建议，后续仍要求明确，列为 D02 待确认。挑战的参考原图、打乱按钮是否保留同样列入 D02，不自行将普通工具完整复制过来。

### 6.2 生命周期与结算（落地约定）

待开始 → 首次拖动 → 进行中 → 全部完成 → 成绩提交中 → 结算成功。暂停可返回进行中；提交失败显示本次结果未入榜并支持重试。

每次重试提交使用同一局标识，避免重复成绩；再挑战使用新的挑战局。结算以有效完整局为准，不信任浏览器随意传来的用时。服务端应检查题目、用户、挑战日期、完成状态及计时事件的一致性；计时权威与校验强度在实现方案中具体化。

每日切换时区、跨日局归属、刷新／断网后是否可恢复有效成绩、暂停与失焦计时、同分排序仍待 D02／D03 确认。未决前不可宣称计时公平性已完全闭合。

### 6.3 完整排行榜

支持今日／往日日期切换，显示排名、用户、完成用时，以及登录用户在选中日期的个人排名；完成时间点为可选字段。榜单为空、尚未参与、结果加载失败各有独立状态。

**落地约定：**相同日期和用户只有一条最佳成绩用于排名；较差的新成绩不覆盖较好成绩。未登录时可读榜，不显示虚构的“我的排名”。旧日期榜单可查看，不因此增加补做往日挑战功能。榜单分页时仍能获取本人的排名。日期时区和同分名次规则依 D03。

## 7. 多人实时拼图

### 7.1 房间流程

普通拼图页 → 一起拼吧（需登录）→ 创建房间 → 展示房间号与邀请链接 → 好友登录加入 → 等待房间 → 房主开始 → 多人进行中 → 共同完成。

- 房间继承房主当前拼图配置和完整进度。例如房主 38%，进入房间后所有人从同一 38% 继续。
- 创建／加入可用弹窗；等待与进行中使用同一个房间路由。
- 分享复制链接是基础邀请能力；原对话出现的微信邀请是否需要独立集成未冻结，见 D06。
- 成员可见头像与在线状态，进行中可见共享进度。
- 房主负责开始；是否允许进行中加入、人数上限和最低开局人数见 D04。

### 7.2 协作规则

某玩家开始拖动一块碎片后，该碎片临时归其操作，其他玩家不能同时拖动；松手后同步位置并释放临时锁。已正确吸附固定的碎片不可被再次移动。

**落地约定：**临时操作锁与正确吸附后的固定状态使用不同字段；锁由统一权威仲裁，不能由两个客户端各自认为获取成功。被占用时可提示“某某正在拖动”。掉线与超时应释放临时锁，重连先同步房间快照，再恢复操作，旧消息不能覆盖新位置或固定状态。

原对话确认掉线后可以重进仍有效的房间。房主退出后的继续方式、房间寿命与关闭权限待 D04。共享工具对所有人还是仅本人的影响待 D05；视图缩放和原图浮窗位置建议仅本地生效，不写入共享棋盘。

### 7.3 进度和完成记录

房间共享进度以同一局为准，不相加各用户的独立百分比。完成时所有在线玩家看到相同完成结果，所有实际参与过的玩家均记录一次完成；“实际参与”的判定阈值、提前离开的参与者结算方式待 D05。

**落地约定：**个人记录按用户与作品去重，房间结算按房间局与参与者防重复；多人结果不进入个人挑战排行榜。房间进度继承后是否回写房主普通局、成员是否获得可单人继续的副本待 D05，避免多人覆盖既有个人存档。

### 7.4 房间状态

创建中、等待中、进行中、重连中、已完成、已结束／过期。加入失败分别解释房间不存在、已满、已结束、无权加入；给重试、返回普通拼图或回首页入口。创建失败保留来源普通局。

V1 不做聊天、语音、实时鼠标轨迹、Emoji 互动和房主踢人。

## 8. 单页创建作品

### 8.1 单页工作区

`/create` 内按操作依赖组织上传、图片调整、作品设置、实时预览和创建按钮。可逐段启用，也可分栏展示，但不进行跨页向导跳转。

| 内容 | 规则 |
|---|---|
| 图片上传 | 必需；选择图片后可进入构图调整；格式、大小、最小尺寸见 D09 |
| 裁剪／构图 | 支持缩放、移动与裁剪，用户可检查最终裁切结果；目标比例见 D09 |
| 作品名称 | 必需；长度上限见 D09 |
| 描述 | 选填；长度上限见 D09 |
| 碎片数量 | 9／16／36／64／121／196／自定义；不能遗漏自定义入口 |
| 自定义片数 | 必须有限制；原对话 9～500 为举例，并非已冻结范围；合法行列组合见 D09 |
| 拼块形状 | 必须提供配置与预览；具体形状枚举见 D09 |
| 可见性 | 公开／仅自己可见；不擅自添加第三种可见性 |
| 预览 | 同页显示最终构图与当前拼图配置，修改设置后同步更新 |
| 创建 | 提交当前图片与设置，成功后展示创建成功弹窗 |

### 8.2 提交与结果

**落地约定：**未通过校验时明确显示问题与修正位置；提交中避免重复创建。成功提示提供开始拼图、前往我的作品，以及权限允许时的分享。不得使用“查看作品”将用户引向被取消的详情页。

格式不支持、文件过大、图片解码失败、上传失败、创建失败须分别可理解；失败保留仍可用的输入并支持重试。更换图片需使旧预览与旧裁剪结果失效。离开有未提交内容的页面时提示，持久化草稿不默认纳入 V1。

公开作品可进入公共发现体系；私有作品仅本人可见，不能在公共搜索或公共卡片接口泄露。私有作品能否通过房间授权给好友待 D06；未定前不能把链接持有等同于访问权限。

分类／标签是否由创建者填写、公开作品进入新上架的审核机制、举报入口及处理方式见 D10／D11。原对话取消详情页后，举报若保留应落在卡片或拼图页菜单内，不为举报重建详情页。

## 9. 我的主页与子页

### 9.1 我的主页

展示个人资料、统计概览、最近玩过摘要、作品／收藏／完成／最近玩过的快捷入口，以及轻量动态摘要。每个摘要通过“查看全部”或侧栏进入对应完整列表；不把全部内容堆成一个无限长后台。

统计值必须与对应列表采用相同口径。“完成数”按去重作品计数，不按同一作品的完成次数累计。摘要显示数量由 UI 规范确定。

### 9.2 四个完整列表

| 页面 | 内容与排序 | 空状态与动作 |
|---|---|---|
| 我的作品 | 本人创建的公开与私有作品；创建时间、游玩人数、可见性；支持最新创建／游玩人数排序 | 暂无作品 → 去创建作品 |
| 我的收藏 | 本人收藏作品；取消收藏同步移出；默认最近收藏优先为落地约定 | 暂无收藏 → 去发现拼图 |
| 我的完成 | 同一作品只出现一次，保留完成标识；默认最近完成优先为落地约定 | 暂无完成 → 去开始拼图 |
| 最近玩过 | 包含进行中和已完成作品；按最近游玩时间降序；按作品聚合为落地约定 | 暂无记录 → 去首页 |

所有列表卡片遵守 F01／F02，完成列表卡片也直接开始新局；存在更新的未完成局时优先恢复。作品失效时说明不可访问，不继续展示私有图片的缓存内容。编辑、删除、批量管理未明确冻结，见第 14 节，不擅自增加操作。

### 9.3 账号、消息、帮助

- 账号设置：个人资料（昵称、头像、简介）、登录方式信息与已讨论的绑定／解绑能力。具体渠道待 D07；落地约定不得解绑最后一种可用登录方式导致无法登录。
- 消息通知：保留页面和有内容／无内容／失败状态；仅展示真实事件，不生成虚构社交动态，通知类型见 D11。
- 帮助与反馈：帮助内容、问题反馈入口与提交结果；具体反馈字段、受理方式和登录要求见 D11。

## 10. 全局状态与异常处理

以下为实施所需的状态要求；不要求为每一种状态创建独立路由。

| 场景 | 状态／反馈 | 恢复与保护 |
|---|---|---|
| 页面／卡片加载 | 骨架或加载提示 | 不显示假数据，不触发提前开局 |
| 搜索无结果 | 展示关键词与筛选 | 修改词／清空筛选／浏览分类 |
| 空个人列表 | 说明为空的原因 | 对应发现或创建入口 |
| 内容加载失败 | 明确失败 | 重试；保留搜索条件 |
| 作品删除、下线或无权访问 | 不可访问提示 | 回来源列表；私有图片不泄露 |
| 登录失败／取消／失效 | 保留原上下文 | 重试或返回；不重复提交操作 |
| 图片格式／大小／解码错误 | 就近说明错误 | 重新选图；保留其他输入 |
| 上传／创建失败 | 失败状态而非成功弹窗 | 重试；避免生成重复作品 |
| 自动保存中／失败 | 清楚标明尚未保存 | 保留可用本地状态并重试 |
| 普通拼图刷新恢复失败 | 不静默清空旧进度 | 重试；明确提示后再决定新开局 |
| 暂停／退出 | 显示相应操作与保存情况 | 继续／退出；挑战计时依 D02 |
| 挑战成绩提交失败 | 本次成绩未入榜 | 防重复重试，不伪造排名 |
| 房间不存在／已满／已结束 | 区分原因 | 返回、重试或重新创建 |
| 多人断网 | 正在重连，暂不可提交拖动 | 恢复快照、释放过期锁 |
| 页面不存在 | 404 状态 | 回首页 |

错误提示避免仅显示内部错误码；开发日志保留排查信息。成功提示必须在持久化或权威响应确认后出现。

## 11. 模式状态与边界

| 维度 | 普通拼图 | 今日挑战 | 多人拼图 |

| 核心目的 | 放松与完成 | 同题速度比较 | 合作完成同一局 |

### 12.1 一致性与权限（落地约定）

- 每张拼图具有稳定碎片标识与配置版本，防止规则变化后恢复错局。
- 收藏和完成列表按用户与作品防重复；每次挑战与房间结算也需防重复处理。
- 私有作品、存档、收藏与个人资料修改均在服务端校验权限，不能只依赖隐藏按钮。
- 在线成员状态与持久化拼图快照分开管理；消息乱序时按版本拒绝旧更新。
- 游玩人数和收藏数须明确口径，不把页面加载、重复刷新和全部开局次数随意混为人数。
- 图片裁剪与形状配置改变可能使旧进度失效；V1 未确认编辑已发布作品，不能直接覆盖现有作品配置。

### 12.2 最小事件记录（落地约定）

可记录作品卡片进入、首次拖动、保存成功／失败、恢复成功／失败、完成、收藏变更、创建提交／成功／失败、房间创建／加入／开始／重连、挑战开始／结算。每个事件携带时间、作品／局／模式和必要的匿名或登录标识，不采集无关个人信息。业务指标目标与数据保留时间待后续发布方案明确。

| 保存可靠性 | 建议普通局关键操作后 2 秒内触发保存，失败可见且能重试；目标与离线策略依 D08 |

| 图片和权限 | 校验实际格式与尺寸，限制资源消耗；私有原图与衍生图均受权限保护；用户文本安全展示 |

## 16. 验收标准

下列用例为交付检查清单，尚未运行。标记“依 Dxx”的用例在对应决策完成后补齐具体预期值；不能把文档检查当成网站已经实现或测试通过。

| 编号 | 场景与操作 | 通过标准 |
|---|---|---|
| AC01 | 游客从首页、搜索、分类、专题点击作品卡片 | 直接进入 `/puzzle/:id`；没有详情中转或普通游玩登录拦截 |
| AC02 | 分别打开未玩、有未完成、已完成作品 | 分别新建、恢复、新开局；有新未完成局优先恢复；旧完成记录仍在 |
| AC03 | 游客触发收藏、创建、多人、我的 | 触发登录；成功继续原动作，取消保留原上下文 |
| AC04 | 登录、退出、切换账户 | 全局 Header 一致；不显示上一账号私有数据 |
| AC05 | 搜索并调整筛选、返回、刷新 | 结果与条件一致；空结果和请求失败可区分并有后续动作 |
| AC06 | 打开分类和首页三类完整列表 | 分类身份／列表来源清晰；可浏览更多；卡片仍直达拼图 |
| AC07 | 对同一作品收藏／取消，检查多个列表 | 状态一致；收藏按钮不进入拼图；失败不假报成功 |
| AC08 | 在 196 片布局下滚动托盘并拖片 | 左右独立滚动、初始整齐排列；中央画布与底部工具可用 |
| AC09 | 拖动、折叠原图，缩放与复位画布 | 不改变主画布分配尺寸、不丢失碎片；控件可再次访问 |
| AC10 | 将碎片放到错误和正确位置 | 错误不计完成；正确吸附固定；全部固定才触发完成 |
| AC11 | 使用普通工具 | 具备四项已确认能力，无分色按钮；具体效果依 D09；不重置已固定片 |
| AC12 | 普通局首次移动、刷新、退出再进入 | 自动记录并恢复同一棋盘，前台不突出竞技计时；存储策略依 D08 |
| AC13 | 模拟保存失败与恢复 | 明确未保存，保留可恢复数据并重试；不静默清空旧局 |
| AC14 | 普通局完成并再拼 | 显示完成反馈，新建一局；我的完成按作品去重 |
| AC15 | 打开今日挑战，等待后首次拖动 | 等待不计时，首次拖动开始正计时；配置不可改，禁用四类禁止能力 |
| AC16 | 连续完成两次同日挑战，一次更慢一次更快 | 榜单始终仅一条用户最佳；进行中时间不入榜 |
| AC17 | 挑战完成后提交失败并重试 | 明确未入榜；成功后展示本次、今日最佳、排名；不重复结算 |
| AC18 | 挑战暂停、失焦、刷新、跨日、同分及游客参与 | 严格按 D01～D03 最终决策测试，规则前后一致 |
| AC19 | 查看今日／往日完整榜单 | 排名、用户、用时及本人排名匹配日期；空榜／未参与表达正确 |
| AC20 | 普通局拼到部分进度后创建房间 | 房间完整继承进度，好友看到一致快照；房主开始进入共享局 |
| AC21 | 两个客户端同时抢同一碎片 | 只有一人取得临时操作权；松手同步并解锁，正确片保持固定 |
| AC22 | 拖动中掉线，再加入房间 | 临时锁按规则释放，重连恢复最新快照；旧消息不回退状态 |
| AC23 | 房间不存在、满员、结束、房主离开 | 有明确反馈与可用出口；容量和生命周期依 D04 |
| AC24 | 多人共同完成并重复收到结算消息 | 同一完成结果；符合 D05 的参与者各记完成且不重复；不上挑战榜 |
| AC25 | 在创建页上传、裁剪、修改设置、预览、创建 | 全程同页；预览与创建一致；六个预设、自定义、形状和可见性均存在 |
| AC26 | 上传无效图片或创建失败 | 依据 D09 校验，错误可修正、输入可保留，重试不重复创建 |
| AC27 | 创建成功后选择开始拼图／我的作品 | 到正确页面，无作品详情；公开／私有访问满足权限策略 |
| AC28 | 他人通过搜索、直接 URL 或图片地址访问私有作品 | 服务端阻止未授权访问；房间授权若允许则按 D06 验证 |
| AC29 | 同一作品完成多次，查看完成和最近玩过 | 完成列表仅一项；最近玩过可含已完成，按最近游玩排序 |
| AC30 | 检查我的四个列表的空态和摘要入口 | 各有完整列表及下一步动作；摘要统计与列表口径相同 |
| AC31 | 检查设置、通知、帮助反馈 | 已确认页面均可达；按 D07／D11 提供真实状态与动作，无虚构通知 |
| AC32 | 在约定桌面设备与网络下测试加载、拖动、保存、多人同步 | 达到 D12 收口后的性能目标；焦点、错误与遮挡问题不阻断核心流程 |
