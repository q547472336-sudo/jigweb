## 2. 阶段与完成门槛

| 阶段 | 任务 | 完成后应能证明 |

| M0 开发输入 | T01～T03 | 路由、状态、UI、技术方案和数据契约一致 |

## 5. M3～M4 执行包

本节是 T14～T18 的实施总览。它不改变 PRD 的规则，只把每个阶段的目标、交付顺序、前后端边界和退出条件集中在一个位置。M3 与 M4 可以并行，但都必须复用 T03 定义的身份、版本、幂等、错误码和服务端权威原则。

### M3 今日挑战

目标：让登录用户完成一个由服务端控制时间、布局和结算的每日正式挑战；游客只能进行明确标注为“不计榜”的练习。

范围：`/challenge` 页面、挑战开始／暂停／恢复／完成、同日固定题目与布局、断网和刷新恢复、跨日失效、最佳成绩和公开排行榜。不包含多人房间，不把普通模式存档转成正式挑战，不新增运营后台。

#### M3 交付分解

1. **挑战配置与读取（T05／T14）**

   - 使用 `daily_challenges` 保存业务日期、Asia/Shanghai 时区、作品版本、行列、形状、seed 和规则版本。
   - 配置按业务日唯一；生效后不可修改；缺题返回“今日挑战暂未开放”，不随机补题。
   - 题目下线时停止新局和在途局，已结算成绩仍可读取但不再暴露图片。

2. **正式局状态和权威计时（T14）**

   - 状态：`ready → starting → active ↔ pausing/paused → submitting → completed`；异常进入 `reconnecting`，无法恢复时明确结束原因。
   - 首次有效拖动才请求开始；服务端确认前不能移动碎片，启动失败允许重试且不计时。
   - 暂停、失焦、断网、刷新都以服务端状态为准；断网遮罩期间禁止操作，未确认的暂停不生效。
   - 服务器记录启动、确认暂停区间和完成时间；客户端时间、失焦时长和网络延迟不能抵扣成绩。
   - 同一用户同一业务日最多一个未结算正式局；第二标签页只读，原连接失效后才可接管。

3. **挑战页面和交互（T14）**

   - 正式挑战固定初始布局和 seed，所有用户当日一致；无打乱、提示、底版、边框和多人入口。
   - 保留可拖动的原图浮窗；暂停或断网时覆盖棋盘、碎片区和原图，并提供继续／退出路径。
   - 显示分秒和毫秒；恢复时优先读取服务端快照，找不到有效局时提示无法恢复并提供重新挑战。

4. **结算与排行榜（T15）**

   - 完成前由服务端验证挑战 ID、作品版本、固定布局、合法操作顺序和最终全部固定状态。
   - 完成事件先保存 attempt，再更新用户最佳成绩，最后返回查询时排行榜快照；请求重试不得重复结算。
   - 同一用户只保留当日最佳；更差成绩不覆盖；同分按完成时间、用户 ID 排序，显示连续名次。
   - 游客练习可记录本地完成，但不能生成正式成绩或排行榜记录。

#### M3 顺序与交接

`T03 契约复核 → T05 挑战配置夹具 → T14 状态／计时／恢复 → T15 结算／榜单 → M3 QA`。

T14 交接给 T15 的最小输入是：挑战 attempt ID、服务端确认状态、有效 elapsed_ms、固定布局版本、最终快照和幂等键。T15 不接收客户端直接提交的用时或排名。

#### M3 退出条件

必须通过 A04～A13、A28 的挑战相关项：游客与正式局边界、同日布局一致、暂停／失焦／断网／刷新恢复、跨日、缺题／下线、第二标签页、完成重试和稳定排名均有测试证据。退出条件未满足时，M3 只能标记“开发完成／待验收”，不能标记 DONE。

### M4 实时协作

目标：让 2～4 名已登录用户在一个来源局的独立副本上实时协作，服务端仲裁碎片锁、位置版本、成员资格和最终完成记录。

范围：公开作品的建房、邀请复制、加入、等待、开始、实时棋盘、锁租约、重连、房主转移、退出、超时和多人结算。不包含私有作品分享、不回写普通存档、不加入挑战榜、不提供全房暂停和打乱。

#### M4 交付分解

1. **房间快照与生命周期（T16）**

   - `ready` 普通局可从 0% 建房；`active` 普通局必须先同步已确认快照再建房；来源局和房间快照相互独立。
   - 房间状态：`creating → waiting → starting → active → completed`；异常可进入 `reconnecting`，超时进入 `ended`。
   - 容量 2～4 人，房主占一席；至少两人在线且仅房主可开始；开始后拒绝从未加入的新成员，已有成员可重连。
   - 等待 30 分钟未开始、全员离线 10 分钟或进行中 24 小时后结束；完成／结束房间不能再次开局。

2. **成员和房主规则（T16）**

   - 第五人返回 `ROOM_FULL`；私有作品在 UI 和服务端都拒绝建房与加入。
   - 房主主动离开立即转移；掉线保留 60 秒，超时转给最早加入的在线成员；没有其他在线成员时暂保留房主身份。
   - 非房主可以离开和重进；房主不能踢人或强制结束全房；等待页开始前重新校验人数和房主身份。

3. **共享棋盘与锁（T17）**

   - 通过 `room:{roomId}` 广播服务端确认的 `snapshot`、`lock`、`move`、`fixed`、`presence`、`state` 事件；广播不代替持久化。
   - 碎片锁为 5 秒租约，持有者每秒续租；松手释放，掉线最长 5 秒释放；没有有效锁不能提交位置。
   - 所有位置事件带锁 token 和 `stateVersion`；旧版本、过期锁、重复事件拒绝，不能回退其他人的新位置。
   - 正确吸附后的固定片永久固定，不因锁到期解除；本人的边框、底版、原图和缩放仅改变本地视图。

4. **协作完成与个人记录（T18）**

   - 至少取得一次锁并提交合法位置变化才算“实际参与”；只加入、观看或抢锁失败不算参与。
   - 房间完成事件幂等处理；实际参与者即使提前离开，最终完成后仍生成一次去重完成记录和一条站内通知。
   - 观看者不生成多人完成记录；多人完成不覆盖任何人的普通局进度，不进入挑战排行榜。
   - 完成页保留 7 天；“再一起拼”创建新房间，不复用旧房间 ID。

#### M4 顺序与交接

`T03 房间契约复核 → T16 建房／加入／生命周期 → T17 实时事件／锁 → T18 完成／通知／个人记录 → M4 QA`。

T16 交接给 T17 的最小输入是：房间快照、成员角色、状态版本、截止时间和当前连接身份。T17 交接给 T18 的最小输入是：服务端确认的固定结果、参与成员集合、房间终态和幂等完成事件。前端只渲染服务端确认结果，不自行裁决锁和完成。

#### M4 退出条件

必须通过 A14～A20、A29 的多人相关项：容量、开始权限、房主转移、三种超时、锁竞争／续租／过期旧消息、重连、实际参与资格、提前离开结算、私有作品拒绝和个人视图隔离均有双客户端或模拟并发证据。未满足时不能标记 M4 DONE。

### M3～M4 共同验收和风险清单

| 领域 | 必须验证 | 失败时回退任务 |
|---|---|---|
| 权威性 | 客户端时间、排名、锁、固定状态不能绕过服务端 | T03、T14、T17 |
| 幂等性 | 开始、暂停、完成、事件、通知重复请求不产生重复结果 | T14、T15、T18、T20 |
| 版本一致性 | 旧快照、旧锁、旧事件不能覆盖新状态 | T10、T14、T17 |
| 重连恢复 | 刷新、断网、失焦、标签页切换均先读取服务端状态 | T10、T14、T17 |
| 权限隔离 | 游客、成员、房主、所有者、维护者权限不串 | T09、T13、T16、T18 |
| 记录口径 | 普通、挑战、多人完成和最近玩过互不覆盖错误数据 | T11、T15、T18 |
| 性能 | 196／500 片与双客户端 100 次同步达到 D12 | T07、T17、T22 |

M3 与 M4 的共同开发前置是 Supabase／生产适配器或等价的可替换权威适配器、服务端时钟夹具、双客户端测试夹具和可重放事件日志。只有内存开发适配器时，可以完成接口和状态机联调，但只能标记本地开发完成，不能宣称生产完成。
